## MotoCam v0.1.10

Release date: 2026-04-02

### Issue Summary

- Day-old recordings were missing from in-app Ride History even though video clips still existed in Gallery.
- Some recorded rides (especially multi-segment sessions) could not be opened after a day.
- Ride discovery relied heavily on `.telemetry.json` sidecar presence, so metadata loss made valid video segments invisible.
- Android recording paths were vulnerable to cache cleanup because camera output originated in temporary storage.

### Resolution

- Switched recording storage base to persistent app documents storage (`MotoCam Recordings`) instead of temporary cache for primary retention.
- Added a persistence step that moves each completed segment into durable storage before metadata/session indexing.
- Hardened telemetry parsing and ride-model recovery:
  - Skip malformed telemetry safely.
  - Keep only segment paths that still exist.
  - Recover sibling video path from telemetry filename when possible.
- Added fallback ride discovery for orphan videos without telemetry so playable clips still appear in history.
- Expanded recording discovery to include:
  - persistent app recordings,
  - legacy temp-cache recordings,
  - Android gallery exports (`/storage/emulated/0/Movies/MotoCam/Videos`).
- Added deduplication between telemetry and video-only entries to avoid duplicate cards.
- Added a visible `VIDEO ONLY (RECOVERED)` badge in ride history for recovered clips without telemetry.
