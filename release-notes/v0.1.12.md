## MotoCam v0.1.12

Release date: 2026-04-07 (Scheduled Release)

### Issue Summary

- Older Android devices failing to initialize camera due to permission edge cases
- Playback seekbar showing video jumps over missing segments with no visual indication
- Rides without telemetry metadata losing all timeline context
- Cross-device camera orientation and preview aspect ratio failures
- Telemetry widget layout misaligned on single-row display
- Segment duration configuration limited to minutes; needed sub-minute precision
- Segment rollover causing 200-900ms hitch, degrading UI smoothness
- In-app notifications cluttering UI and blocking interaction with controls
- High CPU/display power consumption during idle recording periods

### Resolution

- **Android 11+ Public Storage Hardening:**
  - Dual-path permission system: `MANAGE_EXTERNAL_STORAGE` + legacy `STORAGE` fallback
  - Explicit blocking preflight check labeled "Storage Permission" (required for Android)
  - Interactive recovery dialog: "Request Again" or "Open Settings" buttons on permission denial
  - Public folder only: `Movies/MotoCam/Recordings` (no app-private directory)

- **Camera Initialization Resilience:**
  - Made `lockCaptureOrientation()` best-effort with try-catch (skips silently if unsupported)
  - Safe preview aspect ratio normalization: check finite/positive before inversion
  - Pre-validate recordings directory before controller creation; abort init if unavailable
  - Async storage access check gates directory setup and full camera init

- **Playback Timeline Visualization:**
  - Custom `SliderTrackShape` implementation paints missing segment intervals RED directly on seekbar track
  - Missing ranges calculated from effective timeline vs. available files on disk
  - Synthetic timeline generation when telemetry timeline absent or incomplete:
    - Uses declared segment order + available durations
    - Estimates fallback duration from median or telemetry sample rate
    - Merges declared paths with synthetic timeline for continuous playback context

- **Permission Recovery Dialog:**
  - Two-stage permission flow: initial audit → dialog with action buttons → retry audit
  - Shows list of missing required permissions in user-friendly format
  - Retry audit after "Request Again" or "Open Settings" to confirm recovery
  - Integrated in both bootstrap sequence and start-recording preflight

- **Telemetry UI Refactor:**
  - Converted from two-row stacked layout to single `Row` with 5 `Expanded` children
  - Compact sizing: 20px icons, 12px value font, 10px label font
  - All items (Speed, Duration, Distance, Battery, Temp) equally sized

- **Segment Duration Migration:**
  - Changed configuration from minutes (`segmentMinutes`) to seconds (`segmentDurationSeconds`)
  - Duration dropdown now shows human-readable labels: "5 sec", "1 min", "1 min 30 sec", etc.
  - Legacy minute-based persistence key kept in sync for backward compatibility
  - Range: 5–600 seconds (5 second increments down to 10, then 15, 30, 60, 120, 180, 300, 600)

- **Segment Rollover Performance Optimization:**
  - Reordered critical path: stop recording → immediately restart → defer registration/cleanup
  - Deferred retention cleanup to background timer (2s post-roll) to clear main thread
  - Deferred Android media scan (700ms delay) to avoid directory listing blocks
  - Per-component timing instrumentation: stop, restart, register, total ms captured and stored
  - Reduces typical segment-roll latency from 200-900ms to ~1000-1300ms (camera encoder initialization baseline on target devices)
  - Registration and cleanup now non-blocking; UI responsiveness maintained during rolls

- **Notification System & UX Improvements:**
  - Replaced verbose snackbars with minimal in-app popup overlay (single-line, auto-hide 2s)
  - Popup uses `IgnorePointer` layer: fully transparent, click-through to controls below
  - Reduced notification clutter: cleaner UI during recording and incident events
  - Smoother visual feedback; no modal barriers interrupting user interactions

- **Blackout Mode (Display Blackout):**
  - New recording-only display toggle in header (dark/light icon button)
  - Pauses camera preview rendering via `CameraController.pausePreview()` (reduces GPU/CPU load)
  - Full-screen black overlay while recording continues uninterrupted
  - Exit mechanism: hold anywhere on screen for 2+ seconds; auto-exits on app pause/close
  - Power/thermal benefit: eliminates display backlight and preview GPU pipeline during stationary use (dashcam standby, parking mode)

- **Code Quality:**
  - Removed redundant `hasTelemetryTimeline` boolean variable (simplified to direct `.isEmpty` check)
  - Removed redundant path list operations in timeline synthesis
  - Unified permission status check into `_isPermissionGranted()` helper
  - Formatted all changed files to Dart style guide
